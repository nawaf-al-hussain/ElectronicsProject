# Guidelines for Project Demonstration Video — verbatim extraction

**Course:** Electronics Laboratory (EEE 2124) *(file name says "CSE-2124"; document header says EEE 2124)*
**Video type:** Final Project Demonstration
**Maximum duration:** 10 minutes
**Language:** English (mandatory)
**Mode:** Slides + Hardware Demo (faces optional)
*(Source: `../sources/video-submission-guidelines-cse2124.docx`)*

## General instructions

- The video must be professional, well-structured, and clearly narrated.
- Slides can be used for all sections except hardware demonstration.
- The actual hardware must be shown live during feature demonstration.
- Avoid background noise, shaky video, unreadable slides, or poor lighting.
- Videos exceeding 10 minutes may lose marks.
- Keep the Evaluation Rubrics in mind while preparing; address all required aspects.

## Evaluation Rubrics (used for final grading in Project Show)

| Category | Weight |
|---|---|
| Project Idea & Novelty | 15% |
| Real-Life Application and Impact | 15% |
| **Features & Hardware Implementations** | **40%** |
| Cost Effectiveness | 10% |

| Presentation | 10% |
| **Total** | **100%** |

## Required video flow & content

### 1. Introduction & Idea Description *(slides)*
Project title, team information, problem statement, core idea and motivation, why the problem is important — explained simply, understandable to a non-expert.

### 2. Real-Life Applications *(slides)*
Real scenarios, target users (rescue teams, hospitals, industries, public), how the system improves safety/efficiency/automation. "Use realistic examples, not exaggerated claims."

### 3. Core Features & System Overview *(slides)*
- List of major features implemented (**minimum 3**)
- Block diagram / system architecture
- Hardware components used: microcontrollers, sensors, motors/actuators, power supply
- Brief explanation of **why** these components were chosen
- Mention specific model names (e.g., Arduino Uno, ESP32, Raspberry Pi 5)

### 4. Feature Demonstration *(live hardware — NO slides here; "the most important part")*
- Show the actual hardware clearly; demonstrate each major feature one by one
- For each: input given → sensor/motor involved → output/action produced
- Show software output if applicable (Serial Monitor, OLED, app, website)
- Logical flow; system stable and well-assembled
- Skipping trivial features (login/signup, dashboard setup) is allowed; never skip major features or explain without showing

### 5. Costing & Budget Analysis *(slides)*
- Component-wise cost breakdown, total project cost
- Justification of cost-effectiveness; cheaper alternatives if applicable
- "Emphasis should be on performance vs cost, not just low price."

### 6. Future Plans & Possible Extensions *(slides)*
Features to add, hardware/software improvements, scalability/deployment, IoT/AI/advanced-sensor integration — "realistic and technically sound."

### 7. Conclusion *(slides)*
What was achieved, key learning outcomes, final capabilities, clear closing statement.
