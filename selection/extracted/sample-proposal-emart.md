# Sample Proposal — "E-Mart" (format notes)

*(Source: `../sources/sample-project-proposal.pdf`, 7 pages, scanned/OCR'd, by a UIU CSE project team.)*

## What the sample establishes as the expected proposal format

1. **Title page:** project name, 5 authors + student IDs, dept (CSE, UIU).
2. **Abstract:** problem in daily-life terms + one-line solution claim.
3. **Project Overview:** goal, reference to existing solutions (mentions Amazon Go), explicit scoping statement ("we won't use AI/ML; we'll use an RFID module instead" — honest constraint statement), feature list.
4. **Component List:** ESP32, 125 kHz RFID module (RDM6300) + tags, LDR, ultrasonic, L293D motor shield + gear motors + wheels, gas module, flame sensor, servo (door), followed by per-component sections with pin diagrams and feature descriptions (same pattern as the report sample).

## Reuse for our project

Same skeleton works for a CropGuard proposal: abstract (labour-heavy vegetable care → one modular robot) → overview with honest scope (ESP32 real-time + laptop AI assist; water-only spraying in demo) → component list directly from the priced BOM sections A–H → per-component principle sections.
