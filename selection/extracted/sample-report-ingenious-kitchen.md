# Sample Final Report — "Ingenious Kitchen" (format notes)

*(Source: `../sources/sample-project-report.pdf`, 7+ pages, IEEE two-column style, by a UIU CSE project team.)*

## What the sample establishes as the expected report format

1. **IEEE-style layout:** title, authors + student IDs, dept (CSE, UIU), abstract, numbered sections.
2. **Structure:** Abstract → I. Project Overview → II. Component List (numbered) → per-component subsections (A. NodeMCU ESP8266, B. Arduino UNO, C. sensors…) each with specifications + pinout figure + working principle (e.g., ultrasonic `Distance = Speed × Time`) → control/app description (Blynk) → code listings → References (numbered web sources: components101, arduino docs, sensor datasheet pages).
3. **Per-component expectation:** photo/pin diagram + feature list + working principle in plain language.
4. **Code expectation:** full Arduino sketches included inline (setup/loop, sensor read, actuator control).

## Reuse for our project

The CropGuard final report should follow this skeleton: abstract → overview → numbered component list (matching the priced BOM) → per-component principle sections → power-rail diagram → code listings → references. The BOM's "Notes" column already contains the "why chosen" material per component.
